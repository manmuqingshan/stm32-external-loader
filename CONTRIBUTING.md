# Contributing guide

This guide explains how to submit an issue and where to direct other types of
feedback for the STM32 Memory Loaders repository.

## 1. Issues

### 1.1 Before opening an issue

Before opening an issue, please ensure that:

- You are using the latest commit when reproducing the problem.
- The issue is related to the software provided in this repository.
- The issue is not a security vulnerability. For vulnerability reports, see
  [Section 3](#3-vulnerabilities).
- The issue has not already been reported, fixed, or discussed. Please search
  both open and closed issues.

### 1.2 Opening an issue

After checking the points above, open a report from the repository's
[Issues](https://github.com/STMicroelectronics/stm32-memory-loaders/issues)
tab. Please include, when applicable:

- The affected STM32 board, MCU, or memory device
- The loader version or commit
- The development environment and toolchain
- Steps to reproduce the problem
- Relevant build output, logs, or other diagnostic information

Do not include confidential information or security-sensitive details in a
public issue. Please follow the repository's [Code of Conduct](./CODE_OF_CONDUCT.md)
when participating in discussions.

## 2. Pull requests

Pull requests are **not accepted** for this repository. Changes are managed by
STMicroelectronics.

If you have a proposed change, please describe the problem and the proposed
solution in an issue. The maintainers will decide whether and how the change
should be addressed.

## 3. Vulnerabilities

Please do not report a security vulnerability through a public GitHub issue.
Follow the reporting instructions in [SECURITY.md](./SECURITY.md) instead.

## 4. Support requests and miscellaneous

For support requests or topics unrelated to the contents of this repository,
please use the appropriate [ST Community forum](https://community.st.com/t5/product-forums/ct-p/product-forums).

This repository is provided **as-is** and is **not necessarily supported** by
STMicroelectronics.
